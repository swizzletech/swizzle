# HTTP API reference

Generated by `just gen` from the route declarations in [apps/api/src](../../apps/api/src/server.ts). Edit the source, not this page; `just docs-check` fails when the page is stale.

Each route's Access column is its rule in [`ROUTE_ACCESS`](../../packages/runtime/src/http-contract.ts). A `worker` route always requires a live worker bearer token. Worker tokens cannot use control-plane routes. A `session` route requires a signed-in browser session. Other routes that are not `public` require a session cookie, an agent token, or a service account token. Agent tokens act with their person's current rights; service account tokens act in their account's project. An `instance` route also requires an instance owner or admin and otherwise returns HTTP 403 with `ACCESS_DENIED`. A `resource` route asks the access policy about the automation, run or project it names: one the caller may not read returns the same HTTP 404 as one that does not exist, and one the caller may read but not change returns HTTP 403 with `ACCESS_DENIED`, the role the change needs, the grants the caller holds, and the protected environment that capped the role ([the security model](../../docs/explanation/security-model.md)). Lists and counts show only what the caller may read. Routes that take an `environment` query parameter default to the environment the API serves, its `SWIZZLE_ENVIRONMENT` ([`getEnvironment`](../../apps/api/src/http-shared.ts)). Every `GET` route also answers `HEAD`.

Public error codes and their HTTP statuses come from [`API_ERROR_STATUS`](../../packages/core/src/api-errors.ts). Control-plane error bodies contain `code`, `error` and `message`; `code` and `error` name the same catalogue entry. Framework client errors with an unknown code become HTTP 400 with `REQUEST_INVALID`. An empty body sent with `Content-Type: application/json` returns HTTP 400 with `FST_ERR_CTP_EMPTY_JSON_BODY`, and a JSON body containing the NUL character returns HTTP 400 with `REQUEST_BODY_INVALID`. Handler validation uses `REQUEST_INVALID`; automation configuration validation keeps `AUTOMATION_CONFIG_INVALID`.

Access writes report their outcome. A grant returns its role and `previousRole`, which is null for a new grant. Grant removal, protection and team membership return `changed`; removing protection also returns `grantsRemoved`. Project and service-account creation return `changed` beside the created or existing record. The CLI renders these results, including no-ops, without reading access state first. Deleting a project or removing protection with `confirm=false` requests confirmation before making a change.

Resource history routes return the same audit event envelope as `GET /audit`. Resource details are under `change`, and the common event id is `id`. Run responses use `chainOriginRunId` for chain grouping and deduplication and `chainSourceRunIds` for the immediate source runs.

After the auth check, each route checks its path parameters, query and JSON body against the shapes in [`request-validation.ts`](../../apps/api/src/request-validation.ts): run, folder and rule ids are UUIDs, `environment` follows the environment name rule, secret names are uppercase environment variable names, and text from the URL has no control characters. A JSON body field must already have its declared type: the API converts no number, boolean or array to text. A request that does not match returns HTTP 400 with `FST_ERR_VALIDATION` before any lookup.
