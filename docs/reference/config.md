# config.yaml reference

Generated by `just gen` from [`automationConfigRawSchema`](../../packages/config/src/schema.ts). Edit the source, not this page; `just docs-check` fails when the page is stale. `swizzle schema config` prints the same contract as JSON Schema.

Every automation folder holds one `config.yaml`. The parser rejects any field this page does not list and names its path. Runnable examples live in [infra/examples](../../infra/examples/README.md).

## Top-level fields

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `name` | non-empty string | yes | - | Automation name. The platform keys deployments, runs and state on its slug (trimmed, whitespace to `-`, lower-cased), so keep it stable. It is unique across the whole instance: a name that an automation in another project holds, even one you cannot see, fails `swizzle validate`, `swizzle apply --dry-run` and `swizzle apply` with `AUTOMATION_PROJECT_MISMATCH`. |
| `version` | non-empty string | yes | - | Author version. Metadata only: deployments are numbered by the platform as `#seq`. |
| `description` | non-empty string | no | - | One-line summary of the automation. |
| `entrypoint` | non-empty string | no | `"main.py"` | Script the run executes, relative to the automation folder. |
| `trigger` | object, one of the variants below | yes | - | Exactly one trigger; `type` selects the variant. |
| `runtime` | object | no | - | Execution settings. |
| `secrets` | list of string matching `^[A-Z][A-Z0-9_]*$` | no | `[]` | Secret names the run receives as environment variables. Deployed runs read them from the encrypted store of their environment; local `swizzle run` reads them from the shell. |
| `vars` | map of string \| number \| boolean | no | `{}` | Plaintext settings versioned with the code, injected as environment variables and coerced to strings. A name may not start with `SWIZZLE_` or repeat a name in `secrets`. Keys match `^[A-Z][A-Z0-9_]*$`. |
| `connections` | list of string matching `^[a-z](?:[a-z0-9-]{0,58}[a-z0-9])?$` | no | `[]` | OAuth connections the run needs. Each arrives as `SWIZZLE_CONNECTION_<NAME>` (upper-cased, `-` as `_`) with `SWIZZLE_CONNECTION_<NAME>_EXPIRES_AT`. Local `swizzle run` does not resolve them, and deploy fails while one is missing or not active. |
| `api_check` | object, one of the variants below | no | - | How the platform notices that an outside API changed; `mode` selects the level. Required once the automation lists a connection or a secret other than `trigger.signature.secret`. `active` runs a read-only check script on its own schedule, never as a run; `passive` adds no calls and learns only from real runs; `off` needs a reason. Every level records the Deprecation and Sunset headers that SDK `apiFetch` sees. |

## `trigger (type: webhook)`

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `trigger.type` | `webhook` | yes | - |  |
| `trigger.path` | non-empty string | no | - | Ingress path, unique per environment. Local `swizzle run` works without it; deploy fails without it (`TRIGGER_CONFIGURATION_INVALID`), and a path another automation holds fails the deployment. The webhook answers at this exact path on the API. Use `/hooks/` for paths the public listener can receive. |
| `trigger.payload_schema` | map of JSON value | no | - | JSON Schema for the payload. `swizzle run` and webhook ingress reject a payload that does not match it (`WEBHOOK_PAYLOAD_INVALID`) before a run exists. |
| `trigger.signature` | object | no | - | HMAC check over the raw request body, run before a run exists. Webhook ingress answers a missing or wrong signature with the opaque 404 `WEBHOOK_NOT_AVAILABLE` and records a `webhook_rejected` audit event. |

## `trigger.signature`

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `trigger.signature.algorithm` | `hmac-sha256` | no | `"hmac-sha256"` | Signature algorithm over the raw request body. |
| `trigger.signature.encoding` | `hex` \| `base64` | no | `"hex"` | Encoding of the digest in the header. |
| `trigger.signature.header` | string matching `` ^[a-z0-9!#$%&'*+.^_`\|~-]+$ `` | yes | - | Any HTTP header name the sender uses, lower-cased, except the platform's own credential headers (authorization, proxy-authorization, cookie). |
| `trigger.signature.prefix` | string | no | `""` | Text stripped from the header value before the comparison, for example `sha256=`. |
| `trigger.signature.secret` | non-empty string | yes | - | Platform secret that holds the signing key. The run receives it only when `secrets` also lists it. |

## `trigger (type: chain)`

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `trigger.type` | `chain` | yes | - |  |
| `trigger.source` | non-empty string | no | - | Upstream automation. Each of its runs that reaches `on` starts one run of this automation. Set either `source` or `sources`. |
| `trigger.sources` | list of non-empty string | no | - | Two or more distinct upstream automations, not this one. The join fires once per origin run, after every source has a succeeded chain run for that origin. Manual, webhook and cron runs of a source do not count, and the join never fires when a source dead-letters. |
| `trigger.on` | `succeeded` \| `failed` \| `dead-lettered` \| `finished` \| `all-succeeded` | no | `"succeeded"` | Upstream status that fires the trigger. With `source`: `succeeded`, `failed`, `dead-lettered` or `finished`. With `sources`: only `all-succeeded`, which is then the default. |
| `trigger.payload` | `result` \| `payload` \| `full` \| `results` | no | `"result"` | Downstream payload. With `source`: `result` (the upstream result), `payload` (the upstream payload) or `full` (`{ source: { automationName, payload, result, runId, status } }`). With `sources`: only `results`, which is then the default: `{ origin: { automation, runId }, results: { <source>: <result> } }`. |

## `runtime`

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `runtime.execution_mode` | `host` \| `profile` \| `container` | no | `"host"` | How a trusted local `swizzle run` executes: `host` and `profile` as a host process, `container` in the sandbox. Production workers run every deployed run in the container sandbox. |
| `runtime.language` | `python` \| `node` \| `typescript` | no | - | Inferred from the `entrypoint` extension when omitted: `.js` is node, `.ts` is typescript, anything else python. |
| `runtime.on_overlap` | `skip` \| `queue` | no | - | Cron triggers only: what a due tick does while a run of this automation is still active. `skip`, the default, records a skipped tick; `queue` enqueues the run anyway. |
| `runtime.permissions` | object | no | - | Network and filesystem access; see the enforcement table below. |
| `runtime.profile` | string matching `^[a-z][a-z0-9-]{0,63}$` | no | `"host-default"` | Worker group the automation runs in. A run waits for a live worker granted this group, project and environment, and never runs in another group. `swizzle worker groups` lists the groups that serve a project. Unrelated to the CLI's `--profile`. |
| `runtime.queue_timeout` | string | no | `"24h"` | Maximum wait for a worker in this group, such as `24h` or `30m`; then the run is dead-lettered with `PLACEMENT_TIMEOUT`. Waiting consumes no execution attempt. `swizzle diagnose <runId>` says why a queued run waits. |
| `runtime.timeout` | non-empty string | no | `"60s"` | Maximum run time such as `500ms`, `30s`, `5m` or `1h`. Deploy and the worker reject a value above `SWIZZLE_MAX_RUN_TIMEOUT` (default `1h`) unless a timeout grant raises the ceiling for this automation. |
| `runtime.retry` | object | no | - | Retry policy for retryable failures. |
| `runtime.rate_limits` | map of string | no | `{}` | Named limits such as `60/min`. A worker takes one token per group before a run starts; SDK `pace(name)` spaces calls inside a run. |
| `runtime.requirements` | object | no | - | Binaries and dependency manifests the run needs. |
| `runtime.container` | object | no | - | Container sandbox settings. |

## `runtime.requirements.binaries[]`

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `runtime.requirements.binaries[].name` | non-empty string | yes | - | Executable name on the run's `PATH`: the runner image's for a deployed run, this machine's for `swizzle run`. |
| `runtime.requirements.binaries[].version` | string matching `^(?:>=\|<=\|>\|<\|=)?\s*\d+(?:\.\d+)*$` | no | - | A bare numeric version matches a dotted prefix: `25` matches `25.03.0`, and `25.3` matches `25.03.0`. Comparisons `>=`, `<=`, `>`, `<` and `=` compare numeric components, treating omitted components as zero; `=25` means exactly `25.0.0`. Forms such as `^25` are invalid. ## Enforcement of declared fields

Some fields declare intent that only some execution modes enforce.

| Field | Status | Enforcement |
|---|---|---|
| `runtime.execution_mode=container` | `enforced` | Runs in a non-root, read-only container with dropped capabilities, process and resource limits, and an isolated runner network. |
| `runtime.permissions.network` | `container_enforced` | Enforced by container execution. Host/profile execution remains intended for trusted local development only. |
| `runtime.permissions.services` | `container_enforced` | The dispatcher requires the owner's worker service grant and healthy service. The sandbox receives an attempt token for bounded text inference through the named gateway. |
| `runtime.permissions.writable_dirs` | `container_enforced` | Enforced as bounded tmpfs mounts by container execution. Host/profile execution remains intended for trusted local development only. |
| `runtime.rate_limits` | `worker_dequeue_only` | Rate-limit groups are evaluated when a worker prepares execution. They are not public webhook ingress quotas. |
